# Language Learning Assistant with Individual Progress Tracking

## My interpretation of the brief
The project is a database-centred language learning system for one language, English or German. The database stores the learning content (words, meanings, example sentences, topics, difficulty levels) and, more importantly, the complete practice history of every user: which item was asked, whether the answer was correct, when it happened, and how many times the item has been practised. The key idea is that the learner should not see every item equally often. A stored procedure in the database calculates a priority value for each item from the user's history and assembles the next practice sequence from it.

The user interface (web or mobile) is intentionally simple: start a session, answer questions, see progress. It must not contain its own selection logic. The thesis value lies in the data model, the history processing, the two selection strategies and their comparison, and the performance of the priority calculation when the history grows to tens of thousands of answers.

## Why I am a good fit for this project
I want to specialise in database design and database-side logic, and this brief is a good vehicle for that: the interesting part of the system lives entirely inside the database. I also like that the business rules are easy to state in plain language, for example "an item answered incorrectly yesterday must come back sooner than an item answered correctly three times", and then have to be translated precisely into a data model and a stored procedure. This is a clear mapping from a real learning process to a formal model, which is the kind of work I enjoy.

As a language learner myself, I also have a practical understanding of what a good practice sequence feels like, which helps in defining and checking the selection rules.

## Proposed approach
I plan to use Microsoft SQL Server (Developer Edition) with T-SQL, because it is free, has good tooling, and provides Actual Execution Plan, SET STATISTICS IO and SET STATISTICS TIME for the required performance analysis. Oracle with PL/SQL remains an option if the supervisor prefers it. I would target English as the learning language.

I would start with the data model, at least ten related tables in third normal form: users, topics, difficulty levels, learning items, words or expressions, meanings, example sentences, exercises, practice sessions, user answers and a per-user learning state for each item (repetition count, last practice time, correct and incorrect counts, current priority). Keys, referential integrity, uniqueness and important rules (for example, one learning state per user and item) would be enforced at the database level.

The core of the work is the selection logic. I would implement two strategies as stored procedures: a simple rule-based strategy (items never seen first, then items answered incorrectly most recently, then items not practised for the longest time) and a weighted-priority strategy that combines error rate, time since last practice, repetition count and item difficulty into a single score, inspired by spaced-repetition ideas. A procedure would record each answer and update the learning state, and another would assemble the next practice sequence of a requested length for a user.

A reproducible test-data generator would create users, a few thousand learning items and at least several tens of thousands of answers and practice events with realistic patterns. I would write at least ten complex queries (user progress, problematic items, performance by topic, progress over time, repetition statistics, multi-table aggregations) and optimise at least five of them with justified indexes, comparing execution plans before and after. I would also measure how the priority calculation scales as the history grows.

Finally, a simple web interface would let a user start a session, answer questions and see their progress, calling only the database procedures.
